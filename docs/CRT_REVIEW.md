# CRT authenticity review — 2026-09-09

Recommendation: aim for a well-adjusted late-1990s VGA computer monitor. Preserve the finer pattern the user approved. Improve beam reconstruction, density and brightness before adding decorative effects. This is an analysis and implementation brief; the running playtest and renderer are unchanged.

## What we actually render

`PORT/MAC/src/mac_sdl_runtime.cpp` expands the original palette to RGB and supplies the framebuffer, content width and aspect-correct viewport to `PORT/MAC/src/ra_crt_gl.cpp`. The desktop path is one OpenGL 2.1 / GLSL 1.20 pass. It uses nearest source sampling, an approximate 2.2 decode/encode, three horizontal samples, a fixed Gaussian-like vertical brightness multiplier, a screen-anchored staggered RGB slot pattern, local highlight lift and exponential exposure. The approved change doubled mask coordinates, making the repeat 3×4 output pixels. Source scanline spacing did not change. Original 640×400 content uses 5:6 pixel aspect to fill 4:3.

Useful foundations: source artwork/palette untouched; screen-anchored phosphors; separate source-row and mask coordinates; arithmetic performed approximately in linear light; existing clean/CRT split and flat-field patterns. Preserve these.

Important limitations verified in source:

- Lines 121–129: horizontal taps at ±0.65 texels still use nearest filtering. Weights vary with luminance, but sample selection jumps with phase. Vertical processing only multiplies the selected row; it does not reconstruct light from neighboring scanlines. Brightness never changes vertical beam width.
- Lines 130–137: `RA_CRT_MASK_STRENGTH` blends the entire processed image with the untouched image. At default 25, 75% of the linear result is the original sharp framebuffer. It is not an independent phosphor visibility control.
- Lines 134–136: “halation” uses the same three horizontal samples and a center brightness threshold. It cannot produce a two-dimensional halo above/below a bright feature. Exponential exposure changes the tone curve while compensating for the mask.
- Fixed output-pixel mask pitch means different apparent tube density as viewport size changes. The code reads drawable dimensions, but window creation does not request `SDL_WINDOW_ALLOW_HIGHDPI`; verify backing resolution and compositor scaling before claiming physical-pixel calibration.
- Physical-subpixel mode produces an achromatic slot modulation and relies on the actual panel's emitters. BGR swapping only affects the synthetic RGB mode. Do not describe this as universal subpixel calibration; panel layout, orientation and 1:1 presentation matter.
- No temporal persistence or scanout model. Swap interval is explicitly zero. That alone does not prove visible tearing because platform composition and the existing presentation schedule also matter; measure before changing it.
- `tests/crt_mask_test.cpp` tests the older CPU helper in `ra_crt_mask.h`, which the active desktop runtime no longer uses. `input_shim_test.cpp` sets CRT off. Compilation coverage and those passing tests do not establish shader visual correctness.

A CPU evaluation of the existing equations on uniform fields at 400 source lines / 2160 output rows / default strength 25 gives equivalent gray values: 0.25 → 0.2437, 0.5 → 0.4782, 0.75 → 0.7006, white → 0.9183. These are mean linear-light outputs re-encoded with the shader's 2.2 power law, not averages of screenshot code values. Evidence: ignored `build/crt-review/flat-field-audit.json`. This is an analytical check, not a GPU capture or monitor measurement.

## The reference monitor and its limits

Sony's CPD-200GS service manual specifies a 0.25 mm aperture grille and a 312 mm standard image width. Dividing gives approximately 1,248 horizontal grille repeats; a simple three-output-pixel RGB repeat would require 3,744 viewport pixels. At a 2,880-pixel-wide 4:3 viewport on a 4K display, our current mask provides 960 repeats. These are geometric estimates, not measured resolving power. A fine tube cannot be reproduced merely by making every synthetic phosphor fully visible. [Sony service manual, manufacturer document hosted by ManualsLib](https://www.manualslib.com/manual/1069467/Sony-Cpd-200gs.html).

Choose a coherent tube identity: aperture-grille stripes for a Trinitron-inspired preset, or a dot/shadow-mask pattern for a conventional PC tube. Our staggered slot pattern can remain as the current visual preference, but should not be labeled a measured reconstruction of either. CRT-Royale's author documents distinct mask types, configurable beam distributions, resampling and resolution limitations. Use its principles as reference rather than importing its multipass framework. [CRT-Royale author documentation](https://docs.libretro.com/shader/crt_royale/).

A 400-line picture should retain 400 raster rows unless an actual video mode duplicates lines. VGA timing is distinct from game simulation speed; IBM lists 640×400 at 70 Hz among supported modes. This does not establish the exact mode/refresh used by every original Red Alert installation. Preserve the port's game/network timing. [IBM display-mode table](https://www.ibm.com/support/pages/video-overview-ibm-intellistation-m-pro-type-6229).

## Ordered improvements

1. **Reconstruct the beam.** Explicitly fetch neighboring source texels at their centers. Use a small horizontal reconstruction filter and contributions from nearby source rows, with smoothly brightness-dependent vertical width. Integrate or approximate the beam over each destination pixel's footprint, particularly at fractional scaling. Normalize energy as width changes. Desired result: softly connected edges and bright lettering that fills out naturally, while terrain, tiny numerals and selection outlines remain distinct. Start in the existing single pass; no new renderer framework.
2. **Separate mask visibility from image formation.** Keep an overall bypass/comparison control, but make mask contrast independent of focus and beam width. Retain the approved fine pattern initially. Derive density from a chosen virtual tube and viewport size, then filter/attenuate frequencies the output cannot resolve. Never force tiny high-contrast RGB stripes below sampling limits. For widened gameplay, specify whether density remains tied to image height (a wider virtual tube at the same scale) instead of silently stretching a fixed number of triads across every aspect ratio.
3. **Calibrate light and color.** Separate input transfer, mask energy compensation and output encoding. A 2.2 power is an approximation, not exact sRGB. Use a neutral gray ramp and primary ramps to choose the transfer; do not apply a nostalgic tint by default. Preserve black and avoid clipping highlight color. On SDR, mask contrast must trade against peak brightness: no shader can recover unlimited physical luminance. Match broad-area brightness first, then tune local contrast.
4. **Add restrained optical spread only if still needed.** A small spatially two-dimensional light spread around bright lettering, muzzle flashes and explosions could improve glass appearance. Keep its radius/amplitude conservative. Compare a small tap kernel before introducing an extra framebuffer pass; do not blur the entire scene or make dark terrain glow. Additional pass cost must be measured at full drawable resolution.
5. **Optional tube character after the core works.** Slight geometry/edge focus variation and restrained convergence offsets can distinguish monitor presets. Default to well-adjusted geometry and legibility. Any image warp needs matching pointer mapping and edge visibility checks. Large barrel distortion, rolling bars, VHS noise and persistent RGB misalignment are poor defaults for this target.
6. **Treat motion as separate research.** Inspect frame delivery and panning first. A modern sample-and-hold panel cannot gain CRT impulse motion clarity from a static spatial shader. Naive previous-frame blending produces trails, not that clarity. Keep persistence, flicker and black-frame experiments off by default and out of the first change. Any persistence model must use elapsed time, handle scene changes/focus loss and avoid affecting simulation speed.

## Next bounded deliverable and acceptance

Implement only beam reconstruction, independent mask contrast and calibrated brightness first. Preserve the current look as an A/B reference. Use existing test-pattern/capture facilities; add ramps, alternating rows/columns and isolated bright lines to that path rather than creating a parallel renderer. Keep extracted gameplay captures ignored.

Acceptance: original aspect and hit mapping preserved; fine pattern remains stable; no obvious bands or crawling at 1080p/1440p/2160p and fractional window scales; black/gray/primary ramps retain ordering and neutral balance; small sidebar costs and gold menu labels readable at normal viewing distance. Compare title, map, snowy terrain, explosions and panning with equal broad-area brightness, both at 1:1 capture size and normal display size. Record actual window/drawable/viewport dimensions, panel scaling, render timing and dropped-frame behavior. CPU assertions cover math only; compile and real GPU captures cover the active shader, and physical viewing covers perceptual quality. Do not enable global vsync without rechecking the existing presentation schedule and input latency.
